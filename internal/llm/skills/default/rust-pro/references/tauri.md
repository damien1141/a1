# Tauri 2 — Cross-Platform Desktop Apps (Demoted Reference)

Load this reference **only** when the task mentions Tauri. For pure-Rust work, ignore it.

Tauri 2 lets you build desktop (and mobile) apps with a Rust backend and a web frontend. Rust owns truth; the frontend is a rendering layer. IPC payloads are JSON — keep them thin; move heavy data through state handles or `tauri::ipc::Response`.

## Project layout

```
myapp/
├── Cargo.toml                # tauri-build, tauri dep
├── tauri.conf.json           # main config
├── capabilities/             # permission grants
│   └── default.json
├── src/
│   ├── main.rs               # tauri::Builder entry
│   └── commands.rs           # #[tauri::command] functions
└── frontend/                 # web frontend (vite, etc.)
    └── package.json
```

## `main.rs`

```rust
#[cfg_attr(mobile, tauri::mobile_entry_point)]
pub fn run() {
    tauri::Builder::default()
        .plugin(tauri_plugin_opener::init())
        .manage(AppState::default())
        .invoke_handler(tauri::generate_handler![get_user, save_user])
        .run(tauri::generate_context!())
        .expect("error while running tauri application");
}

fn main() { run(); }
```

## Commands — the IPC boundary

```rust
#[derive(serde::Serialize)]
pub struct User { id: String, name: String }

#[tauri::command]
pub async fn get_user(id: String, state: tauri::State<'_, AppState>) -> Result<User, String> {
    state.users.lock().unwrap().get(&id).cloned().ok_or("not found".into())
}
```

- Every command must be registered: `generate_handler![get_user, save_user]`
- **Unregistered commands compile fine and fail silently at runtime** — registration is a post-compile checklist item
- Errors should implement `serde::Serialize` (or use `tauri::ipc::InvokeError`)

## State — `State<'_, T>` requires `T: Send + Sync + 'static`

```rust
use std::sync::Mutex;

#[derive(Default)]
pub struct AppState {
    pub users: Mutex<std::collections::HashMap<String, User>>,
}

// Register with .manage(AppState::default())
// Access in commands via State<'_, AppState>
```

Non-`Send` state in an async command → compile error.

## Events — `app.emit`

```rust
use tauri::{Emitter, Manager};

#[tauri::command]
pub async fn process(app: tauri::AppHandle, file: String) -> Result<(), String> {
    for chunk in chunks(&file) {
        app.emit("progress", &chunk).map_err(|e| e.to_string())?;
    }
    Ok(())
}
```

**Requires `use tauri::Emitter;`** — without the trait import, you'll see "no method named `emit` found".

## Channels — for streaming per-caller

```rust
use tauri::ipc::Channel;

#[tauri::command]
pub async fn download(url: String, on_progress: Channel<u64>) -> Result<(), String> {
    let total = 1024 * 1024;
    for i in 0..10 {
        on_progress.emit(i * 100).ok();
        tokio::time::sleep(std::time::Duration::from_millis(100)).await;
    }
    Ok(())
}
```

Use `Channel<T>` for per-caller streaming. Events are global; channels are per-call. **Using events for request/response causes cross-talk between callers.**

## Capabilities & permissions

```json
// capabilities/default.json
{
  "$schema": "../gen/schemas/desktop-schema.json",
  "identifier": "default",
  "description": "default capabilities",
  "windows": ["main"],
  "permissions": [
    "core:default",
    "opener:default"
  ]
}
```

- Every permission used must be granted here
- The ground truth schema is `target/schema.json` (regenerated by `cargo build`)
- File system and shell scopes are extra-restricted; configure explicitly

## Plugins — 4-step wiring

For each plugin (e.g. `tauri-plugin-opener`):

1. **Cargo dep**: `tauri-plugin-opener = "2"` in `Cargo.toml`
2. **JS pkg**: `npm install @tauri-apps/plugin-opener` in the frontend
3. **Init in Rust**: `.plugin(tauri_plugin_opener::init())` on the builder
4. **Permission grant**: add `"opener:default"` to the capability JSON

Any missing step → runtime "not allowed" or "plugin not found". The compiler will not catch this.

## Frontend invocation (TypeScript)

```ts
import { invoke } from "@tauri-apps/api/core";

const user = await invoke<User>("get_user", { id: "u1" });

// Channels
import { Channel } from "@tauri-apps/api/core";
const onProgress = new Channel<number>();
onProgress.onmessage = (n) => console.log("progress", n);
await invoke("download", { url: "...", onProgress });
```

## Mobile

Tauri 2 supports iOS and Android. Use `#[cfg_attr(mobile, tauri::mobile_entry_point)]` on the run function. Mobile has different permissions and lifecycle; test on a real device or simulator.

## Verification for Tauri

```bash
cargo fmt --check
cargo clippy --all-targets -- -D warnings
cargo test
cargo audit
# Frontend
cd frontend && npm run lint && npm run build
# Smoke (manual or scripted)
cargo tauri dev
```

Plus the Tauri-specific checklist:
- [ ] Every new `#[tauri::command]` is in `generate_handler![...]`
- [ ] Every plugin completed all 4 wiring steps
- [ ] Every permission used is in `capabilities/default.json`
- [ ] `use tauri::Emitter;` imported where `emit` is called

Unregistered commands compile fine and fail silently at runtime — this is the #1 Tauri bug class. **Prove the boundary after wiring.**

## Common pitfalls

- Forgetting `use tauri::Emitter;` → "no method named emit"
- `State<'_, T>` with non-`Send` `T` → compile error
- Mixing event-based request/response → cross-talk; use `Channel<T>`
- Granting `core:default` and assuming FS/shell work → those need explicit scope config
- Calling `unwrap()` on `lock()` in async — poisons mutex; use `?` with error conversion
- Frontend not rebuilt before `tauri build` → stale assets in the bundle
